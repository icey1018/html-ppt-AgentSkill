// current state

仅靠 Prompt，团队常见 3 个痛点

不可复用

同一任务换个人就重写一遍，经验沉淀不了。

❌ 重复劳动

不可预测

输入略变，输出风格和结构就漂移，评审成本很高。

❌ 质量波动

不可治理

缺少统一模板、测试和版本管理，难以规模化。

❌ 难以放大

skill anatomy

一个可落地的 Skill，至少包含这 5 层

把「会做」变成「谁来都能做」：规则、模板、脚本、校验、示例缺一不可。

1. 任务边界 2. 输入约束 3. 输出模板 4. 自动检查 5. 迭代记录

workflow

标准交付流程：4 步闭环

需求清晰化 → 模板化生成 → 自动化校验 → 人工精修，是最稳妥的路径。

① Define：目标 / 受众 / 页数
② Generate：按模板产出初稿
③ Verify：结构与规范检查
④ Refine：叙事和视觉优化

质量门禁建议

· 每页仅 1 个核心信息点
· 保证页数与需求一致
· 样式 token 不写死颜色
· 必须可键盘演示与跳转

metrics

上线后，重点盯 3 个指标

交付时长

从需求到首稿的平均时间，目标下降 40%+。

返工率

结构性返工占比，目标控制在 15% 以下。

复用率

同类任务直接复用技能包的比例，目标持续提升。

建议按周复盘：指标趋势 + 失败样本 + 下一版改动清单。

// takeaways

三句话总结

先标准化

把高频任务做成模板，先求稳，再求花哨。

再自动化

把检查前置成脚本，让质量可重复。

最后规模化

用版本管理和案例库，让团队共享能力增长。
